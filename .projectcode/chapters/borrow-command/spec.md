# borrow-command 대출 요청 검사

종류: 기능
배울 것: 입력 모델, 입력 검사 위치

## 먼저 볼 문제

빈 회원 번호로 대출된다
- 회원 번호를 비우고 B1을 대출하면 대출했습니다가 나온다. 목록을 보면 B1은 대출 가능이다
- 회원 번호에 빈칸 하나를 넣고 B2를 대출하면 저장 파일에 빈칸 회원이 남는다
- 다시 켜도 B2는 대출 중인데 빌린 사람이 없다
- 들어오는 포트가 글자 두 개를 그대로 받아서 아무도 값을 검사하지 않는다

```
1 대출  2 반납  3 목록  0 종료
> 1
회원 번호: 
책 번호: B1
객체지향의 사실과 오해 대출했습니다
```

## 할 일

- S1 들어오는 포트의 대출은 대출 요청 하나를 받는다. 대출 요청은 회원 번호와 책 번호를 담은 입력 모델이다. 콘솔 메뉴와 두 번째 입구는 대출 요청을 만들어 포트를 부른다
- S2 대출 요청은 만들 때 형식을 검사한다. 회원 번호나 책 번호가 비었거나 빈칸뿐이면 잘못된 값 오류로 만들어지지 않는다
- S3 콘솔 메뉴에서 회원 번호를 비우거나 빈칸만 넣고 대출하면 오류로 멈춘다. 대출했습니다가 나오지 않고 저장 파일에 대출이 남지 않는다

## 검사 위치

| 검사 | 예 | 자리 |
|---|---|---|
| 형식 검사 | 회원 번호가 비었나 | 입력 모델 대출 요청 |
| 업무 규칙 | 이미 대출 중인 책인가 | 도메인 책 |

- 형식 검사는 저장된 책을 보지 않아도 할 수 있다. 그래서 포트 안으로 들어오기 전에 막는다
- 업무 규칙은 책의 지금 상태를 알아야 한다. 그래서 도메인 책에 그대로 둔다

## 실행 예시

```
1 대출  2 반납  3 목록  0 종료
> 1
회원 번호: 
책 번호: B1
Exception in thread "main" java.lang.IllegalArgumentException: 회원 번호가 비었습니다
```

## 흐름

메뉴 1 -> 회원 번호와 책 번호 읽기 -> 대출 요청 만들기(형식 검사) -> 대출 유스케이스 -> 도메인 책 대출(업무 규칙) -> 저장

## 그대로인 것

- 바른 값으로 대출하면 결과 글은 book-list와 같다
- 반납은 책 번호 글자 하나를 그대로 받는다
- 두 번째 입구의 실행 결과는 book-list와 같다
- 대출 중인 책을 다시 대출하면 오류로 멈춘다

## 안 하는 것

- 빈 값 오류를 메시지로 알리고 메뉴로 돌아가기: loan-errors 장
- 반납 요청 입력 모델: 안 만듦. 책 번호 하나라 글자 그대로 받는다
- 회원 번호 모양 검사(M으로 시작하는가): 안 만듦
