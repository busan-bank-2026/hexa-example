# due-date 반납 기한

종류: 기능
배울 것: 시계 포트, 시간 갈아 끼우기

## 먼저 볼 문제

연체를 확인하려면 14일을 기다려야 한다
- 서비스가 시스템 날짜를 직접 읽어 반납 기한과 연체를 정하면 오늘이 아닌 날을 실행해 볼 수 없다
- 오늘 빌린 책은 15일 뒤에야 연체가 된다. 연체 표시를 보려면 14일을 기다리거나 컴퓨터 날짜를 바꿔야 한다
- 첫 task가 이 모습을 먼저 만든다

```
1 대출  2 반납  3 목록  0 종료
> 3
B1 객체지향의 사실과 오해 대출 중 반납 기한 2026-11-30
B2 클린 아키텍처 대출 가능
B3 도메인 주도 설계 첫걸음 대출 가능
```

## 할 일

- S1 대출하면 반납 기한을 오늘부터 14일 뒤로 정한다. 콘솔 메뉴는 대출 결과 아래에 반납 기한을 보여 준다
- S2 저장 파일 한 줄 끝에 반납 기한을 더한다. 껐다 켜도 기한이 남고 반납하면 기한이 비워진다
- S3 목록은 대출 중인 책의 반납 기한을 보여 주고 오늘이 기한을 지난 책에 연체를 붙인다
- S4 서비스는 오늘 날짜를 나가는 포트인 시계 포트에 묻는다. 서비스와 도메인은 시스템 날짜를 직접 읽지 않는다
- S5 시계 어댑터를 갈아 끼운다. Main은 시스템 날짜 시계를 끼우고 두 번째 입구는 날짜를 정해 둔 시계를 끼워 15일 뒤 연체를 바로 보여 준다

## 실행 예시

오늘이 2026-11-16일 때

```
1 대출  2 반납  3 목록  0 종료
> 1
회원 번호: M1
책 번호: B1
객체지향의 사실과 오해 대출했습니다
반납 기한: 2026-11-30
1 대출  2 반납  3 목록  0 종료
> 3
B1 객체지향의 사실과 오해 대출 중 반납 기한 2026-11-30
B2 클린 아키텍처 대출 가능
B3 도메인 주도 설계 첫걸음 대출 가능
1 대출  2 반납  3 목록  0 종료
> 0
프로그램을 끝냅니다
```

저장 파일

```
B1,객체지향의 사실과 오해,M1,2026-11-30
B2,클린 아키텍처,,
B3,도메인 주도 설계 첫걸음,,
```

두 번째 입구

```
B1을 M1에게 대출: 객체지향의 사실과 오해
반납 기한: 2026-03-16
15일 뒤 B1 연체: true
B1 반납: 객체지향의 사실과 오해
```

## 흐름

대출 -> 서비스가 시계 포트에 오늘을 묻기 -> 오늘 + 14일을 기한으로 저장 -> 목록에서 오늘과 기한 비교 -> 지났으면 연체

## 그대로인 것

- 대출, 반납, 목록의 실패 메시지는 loan-errors와 같다
- 메모리 저장 어댑터는 그대로다

## 안 하는 것

- 연체 알림 보내기: overdue-notice 장
- 예전 모양 저장 파일 읽기: 안 만듦. 앞 장에서 만든 저장 파일은 지우고 시작한다
- 연체료, 연체 회원 대출 막기, 기한 연장: 안 만듦
