# file-store 파일 저장

종류: 기능
배울 것: 어댑터 갈아 끼우기, 저장 모델 매핑

## 먼저 볼 문제

프로그램을 끄면 대출 기록이 사라진다
- B1을 M1에게 대출하고 프로그램을 끝낸다
- 다시 실행해 B1을 M2에게 대출하면 그대로 대출된다
- 책이 메모리에만 있어서 끄면 처음 책 3권으로 돌아간다

## 할 일

- S1 책을 파일에 저장하는 드리븐 어댑터를 더한다. 한 줄에 책 하나이고 책 번호, 제목, 대출한 회원 번호를 쉼표로 나눠 적는다
- S2 어댑터는 파일 한 줄을 책으로 되살린다. 대출 중이던 책은 대출 중인 책으로 되살아난다
- S3 저장 파일이 없으면 처음 책 3권으로 시작한다
- S4 Main은 메모리 저장 대신 파일 저장을 끼운다. 서비스는 고치지 않는다. 프로그램을 껐다 켜도 대출 기록이 남는다

## 저장 파일

hexa/data/books.txt

```
B1,객체지향의 사실과 오해,M1
B2,클린 아키텍처,
B3,도메인 주도 설계 첫걸음,
```

- 대출 중이 아닌 책은 회원 번호 칸이 비어 있다

## 실행 예시

```
첫째 실행: 1, M1, B1, 0 -> 객체지향의 사실과 오해 대출했습니다
둘째 실행: 1, M2, B1 -> 이미 대출 중인 책입니다 오류로 멈춘다
셋째 실행: 2, B1 -> 객체지향의 사실과 오해 반납했습니다
```

## 흐름

메뉴 -> 서비스 -> 나가는 포트 -> 파일 어댑터 -> 책을 한 줄로 바꿔 파일에 쓰기 -> 다음 실행에서 한 줄을 책으로 되살리기

## 그대로인 것

- 메뉴의 동작과 글은 hexagon-packages와 같다
- 두 번째 입구는 메모리 저장을 그대로 쓴다
- 대출 중인 책을 다시 대출하면 오류로 멈춘다

## 안 하는 것

- 저장 파일이 깨졌을 때 알리기: 안 만듦
- 대출 실패 메시지: loan-errors 장
- 실제 DB 저장: oracle-store 장
