# overdue-notice 연체 알림

종류: 기능
배울 것: 알림 포트, 어댑터 하나 더 꽂기

## 할 일

- S1 메뉴에 4 연체 알림을 더한다. 고르면 연체된 책마다 빌린 회원에게 알림을 보내고 연체 알림 N건을 보냈습니다를 보여 준다
- S2 알림 글은 책 제목, 반납 기한, 지났다는 말을 담는다. 연체가 아닌 책과 빌리지 않은 책에는 보내지 않는다
- S3 서비스는 알림을 나가는 포트인 알림 포트로 보낸다. 서비스는 알림이 어디로 가는지 모른다
- S4 콘솔 알림 어댑터는 받는 회원과 알림 글을 콘솔에 찍는다. 두 번째 입구는 콘솔 알림을 끼워 15일 뒤 연체 알림을 바로 보여 준다
- S5 파일 알림 어댑터를 하나 더 꽂는다. 알림을 저장 폴더의 알림 파일에 한 줄씩 더한다. Main은 한 줄만 바꿔 파일 알림을 끼우고 두 번째 입구는 콘솔 알림 그대로다

## 실행 예시

B1 반납 기한이 지난 저장 파일로 시작할 때

```
1 대출  2 반납  3 목록  4 연체 알림  0 종료
> 4
연체 알림 1건을 보냈습니다
1 대출  2 반납  3 목록  4 연체 알림  0 종료
> 0
프로그램을 끝냅니다
```

알림 파일

```
M1,객체지향의 사실과 오해 반납 기한 2020-01-01이 지났습니다
```

두 번째 입구

```
B1을 M1에게 대출: 객체지향의 사실과 오해
반납 기한: 2026-03-16
15일 뒤 B1 연체: true
M1에게 알림: 객체지향의 사실과 오해 반납 기한 2026-03-16이 지났습니다
연체 알림: 1건
B1 반납: 객체지향의 사실과 오해
```

## 흐름

4 연체 알림 -> 서비스가 시계 포트에 오늘을 묻기 -> 연체된 책 고르기 -> 알림 포트로 회원에게 보내기 -> 끼운 어댑터가 콘솔이나 파일로 -> 보낸 수

## 그대로인 것

- 대출, 반납, 목록과 실패 메시지는 due-date와 같다
- 저장 파일 모양은 그대로다

## 안 하는 것

- 이메일, 문자 같은 진짜 알림 보내기: 안 만듦. 바깥 서버가 필요하다
- 같은 연체에 알림을 한 번만 보내기: 안 만듦
- 알림 파일 읽어 보기 메뉴: 안 만듦
